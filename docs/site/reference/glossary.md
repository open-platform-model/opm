| Term | Definition |
| --- | --- |
| Module | <!-- `#Module`: the published description of an application, made of components, a configuration schema (`#config`) and example values (`debugValues`); versioned and distributed as a CUE module through an OCI registry. Closest to a Helm chart, without templates. Check against: core/src/module.cue, core/SPEC.md (section 3.2) --> |
| Component | <!-- `#Component`: one deployable unit inside a module, usually one workload, built by attaching resources, traits and blueprints; its `spec` is the unification of what it attaches. Check against: core/src/component.cue, core/SPEC.md (section 3.1) --> |
| Primitive | <!-- The collective name for resources, traits and blueprints: the building blocks a catalog publishes and a module attaches, each keyed by a contract and carrying an `apiVersion`. Transformers are not primitives. Check against: core/SPEC.md (section 1) --> |
| Resource | <!-- `#Resource`: a primitive for something that must exist at runtime, such as a container, a volume, a ConfigMap or a Secret. Not a Kubernetes kind: which objects it becomes depends on the transformers that match it. Check against: core/src/resource.cue, catalog_opm/opm/resources/v1beta1/ --> |
| Trait | <!-- `#Trait`: a primitive that changes how a component's resources behave, such as scaling, exposure or a security context; `appliesTo` lists the resources it may attach to. Check against: core/src/trait.cue, catalog_opm/opm/traits/v1beta1/ --> |
| Optional trait | <!-- A trait whose `optional` field resolves to `true`: when no transformer on the platform handles it the render continues with a warning; when `false`, the render fails. The catalog states the posture as a default and a component may override it where it attaches the trait. Check against: core/src/trait.cue, core/SPEC.md (section 2.2) --> |
| Blueprint | <!-- `#Blueprint`: a primitive that composes resources and traits into one attachable unit and answers the component's matching label, such as `stateless-workload` or `stateful-workload`. Choosing a blueprint is the nearest thing to choosing Deployment or StatefulSet. Check against: core/src/blueprint.cue, catalog_opm/opm/blueprints/v1beta1/ --> |
| Wrapper | <!-- A ready-made `#Component` fragment a catalog ships for one primitive, such as `#StatelessWorkload` (a blueprint), `#Expose` (a trait) or `#ConfigMaps` (a resource); a module embeds wrappers into its component instead of attaching the primitive by its contract key. Check against: modules/web_app/components.cue, catalog_opm/opm/traits/v1beta1/graceful_shutdown.cue (`#GracefulShutdown`), catalog_opm/opm/resources/v1beta1/configmap.cue (`#ConfigMaps`) --> |
| Module configuration (`#config`) | <!-- The schema, with defaults, that a deployer's values must satisfy; written by the module author and expressible in OpenAPI v3. Check against: core/src/module.cue, core/SPEC.md (section 3.2) --> |
| `debugValues` | <!-- Example values a module ships so it can be built without an instance file; used by `opm module build`, `opm module apply` and `opm module vet` when no `-f` is given. Check against: core/src/module.cue, cli/internal/cmd/module/build.go --> |
| Values | <!-- The concrete configuration a deployer supplies for one instance: the `values` field of an instance, `values.cue` beside an instance file, or files passed with `-f`. Several sources are unified, so two different values for one field conflict. Check against: core/src/module_instance.cue, cli/internal/cmd/instance/build.go, library/docs/getting-started.md --> |
| Layering contract | <!-- The rule for which layer may write which kind of value onto a component field: resources and traits give bounds only, a blueprint at most one default per field, the module author defaults only inside `#config`, and a transformer falls back only when a field is absent. Nothing checks it (convention). Check against: core/SPEC.md (section 6) --> |
| Instance | <!-- `#ModuleInstance`: one deployed copy of a module, binding it to values, a name and a namespace. Closest to a Helm release. Check against: core/src/module_instance.cue, core/SPEC.md (section 3.5) --> |
| Synthetic instance | <!-- An instance the CLI builds around a module directory so it can render without an instance file; named `<module>-debug` in namespace `default` unless `--name` or `--namespace` is given. Check against: cli/internal/workflow/render/module.go, cli/internal/cmd/module/apply.go --> |
| `resourceName` | <!-- `metadata.resourceName` on a component: the name its rendered objects get, `<instance>-<component>` by default, overridable per component. Check against: core/src/component.cue --> |
| `#names` | <!-- The names a component computes once from its `resourceName` and its instance: `resourceName` and the DNS forms `dns.short`, `dns.local` and `dns.fqdn`; other components read them through `#ctx.components`. Check against: core/src/component.cue, core/src/module.cue, core/src/module_context.cue (`#ComponentNames`) --> |
| Transformer | <!-- `#ComponentTransformer`: a function a catalog ships that turns a matched component into Kubernetes objects; it declares the labels, resources and traits a component must carry to match. Check against: core/src/transformer.cue, core/SPEC.md (section 4.1) --> |
| Matching | <!-- How the render pairs components with transformers: a transformer matches a component when the component carries every required label, resource and trait; every matching transformer runs. Check against: core/src/transformer.cue, library/opm/kernel/doc.go --> |
| Verdict | <!-- The render's per-candidate result of matching one transformer against one component: matched or not, with the required labels the component lacked; unmatched components are reported with their verdicts (`CandidateVerdict`). Check against: library/opm/errors/unmatched.go, library/opm/errors/match.go (`UnifyRefusal`) --> |
| `matchLabels` | <!-- A component's matching identity, gathered from what it attaches (the catalog's key is `core.opmodel.dev/workload-type`); compared with a transformer's `requiredLabels` at render time and never on the cluster. Distinct from `metadata.labels`, which is descriptive. Check against: core/src/component.cue, core/src/resource.cue, catalog_opm/opm/blueprints/v1beta1/stateless_workload.cue --> |
| Workload type | <!-- The matching label `core.opmodel.dev/workload-type`, with the values `stateless`, `stateful`, `daemon`, `task` and `scheduled-task`; the container resource requires it and a blueprint answers it, and it selects the Deployment, StatefulSet, DaemonSet, Job or CronJob transformer. Check against: catalog_opm/opm/resources/v1beta1/container.cue, catalog_opm/opm/blueprints/v1beta1/, catalog_opm/opm/transformers/ --> |
| Contract | <!-- The key a module demands and a catalog defines, `<path>/<name>@<apiVersion>`, for example `opmodel.dev/catalogs/opm/resources/container@v1beta1`; a resource, trait or blueprint is identified by its contract. Check against: core/src/types.cue (`#ContractFQNType`), core/src/resource.cue --> |
| Contract level (`apiVersion`) | <!-- A primitive's own version on the Kubernetes ladder (`v1alpha1`, `v1beta1`, `v1`), moved only by a breaking change; the additive-only promise applies at beta and GA. Check against: core/src/types.cue (`#APIVersionType`, `#APIVersionGated`) --> |
| Additive-only promise | <!-- The rule that a contract at a beta or GA level only gains fields; a breaking change needs a new `apiVersion`. Alpha levels promise nothing. `opm catalog publish` compares members against earlier published builds. Verify: which comparisons the publish compatibility gate runs and which it exempts. Check against: core/src/types.cue (`#APIVersionGated`), cli/internal/publish/compat.go --> |
| Fulfilment | <!-- `fulfilment` on a resource or trait: `catalog` (the declaring catalog ships the transformer, the default) or `provider` (another catalog must supply it). Check against: core/src/resource.cue, core/src/trait.cue --> |
| Provider | <!-- A catalog whose transformers implement a provider-fulfilled contract another catalog defines; a platform carries at most one per contract. Check against: core/src/platform.cue (`overSubscribed`), opm-operator/api/v1alpha1/transformerregistration_types.go --> |
| Catalog | <!-- `#Catalog`: a versioned CUE module that lists the resources, traits and blueprints it defines and the transformers it implements. Check against: core/src/catalog.cue, core/SPEC.md (section 3.6) --> |
| Abstraction catalog | <!-- `opmodel.dev/catalogs/opm@v4`: the first-party catalog of abstractions (container, volumes, blueprints, traits) that modules start from. Check against: catalog_opm/opm/catalog.cue, catalog_opm/opm/identity/ --> |
| Raw Kubernetes catalog | <!-- `opmodel.dev/catalogs/k8s@v1`: the first-party catalog that carries native Kubernetes kinds through as-is, one object per component, with no traits and no blueprints; the escape hatch when no abstraction fits. Verify: the "no traits" and "one object per component" claims against the k8s transformers. Check against: catalog_opm/k8s/catalog.cue, catalog_opm/k8s/resources/v1/, catalog_opm/k8s/transformers/ --> |
| Platform | <!-- `#Platform`: the set of catalogs a render may use, as a CUE module whose `#registry` imports each catalog; on a cluster, the `Platform` resource (a cluster-scoped singleton named `cluster`) from which the operator generates that module. Check against: core/src/platform.cue, opm-operator/api/v1alpha1/platform_types.go --> |
| Platform module | <!-- The CUE module holding a platform: `cue.mod/module.cue` pins each catalog build, `platform.cue` imports the catalogs. The pins decide which builds a render uses. Check against: core/src/platform.cue, cli/internal/config/templates.go, cli/internal/cmd/platform/pull.go --> |
| Local default platform | <!-- `~/.opm/platform/`, the platform module `opm config init` writes; used when no `--platform` is given and, for commands that read the cluster, no cluster `Platform` is readable. Check against: cli/internal/config/templates.go, cli/internal/platform/resolve.go --> |
| Contract inventory | <!-- `#contracts` on a platform: which contracts the enabled catalogs define, which transformers require each, and the reports `unfulfilled`, `overSubscribed` and `comparable`; shown by `opm platform check`. Check against: core/src/platform.cue (`#ContractInventory`), cli/internal/cmd/platform/check.go --> |
| Kernel | <!-- The Go library (`library/opm/kernel`) that acquires modules, instances and platforms, validates values and renders; the CLI and the operator both embed it. It applies nothing. Check against: library/opm/kernel/doc.go --> |
| Render | <!-- Turning an instance into Kubernetes objects against a platform, in one CUE build: `opm instance build`, `opm instance vet`, and the first half of `opm instance apply` and of an operator reconcile. Check against: library/opm/kernel/doc.go, cli/internal/cmd/instance/build.go --> |
| Module path | <!-- An artifact's complete CUE module path including its major, such as `opmodel.dev/modules/web_app@v1`; the same string in `cue.mod/module.cue`, the import statement and the registry coordinate. Check against: core/src/types.cue (`#ModulePathType`), core/src/module.cue --> |
| Registry path | <!-- The module path without its `@vN` major, such as `opmodel.dev/modules/web_app`; the OCI repository the versions live under, and part of instance identity. Check against: core/src/types.cue (`#ArtifactRef`), core/src/module.cue --> |
| Major | <!-- The `@vN` suffix of a module path; an artifact's major changes only with a breaking release, and its version's major must agree. Check against: core/src/types.cue (`#ArtifactRef`), core/src/identity_package.cue --> |
| Version | <!-- An artifact's SemVer release, `metadata.version` on a module or catalog, declared in its identity package. Not part of a module's identity. Check against: core/src/module.cue, core/src/catalog.cue, core/src/identity_package.cue --> |
| Catalog version | <!-- `metadata.catalogVersion` on a primitive or transformer: the catalog release it shipped in, stamped by the catalog. Provenance only for primitives; part of a transformer's key. Check against: core/src/catalog.cue, core/src/resource.cue, core/src/transformer.cue --> |
| FQN | <!-- `metadata.fqn`, an artifact's or member's full key: a module's or catalog's FQN is its module path; a primitive's is its contract; a transformer's ends in the catalog release (`…/transformers/deployment-transformer@4.4.0`). Check against: core/src/types.cue (`#FQNType`, `#ImplFQNType`), core/src/module.cue, core/src/transformer.cue --> |
| Identity package | <!-- The `identity/identity.cue` file every module and catalog commits, holding `ModulePath` and `Version`; `opm module vet` and the publish commands check it against `#IdentityPackage`. Check against: core/src/identity_package.cue, cli/internal/cmd/module/vet.go, cli/internal/publish/identity.go --> |
| Instance UUID | <!-- `metadata.uuid` on an instance, computed from the module's registry path, the instance name and the namespace; unchanged by module upgrades. Every rendered object carries it in the `module-instance.opmodel.dev/uuid` label, which pruning compares. Check against: core/src/module_instance.cue, opm-operator/internal/reconcile/moduleinstance.go --> |
| Version skew | <!-- A module's `cue.mod/module.cue` requiring a newer build of core or a catalog than the platform pins. The render warns by default and refuses when the skew policy is `refuse` (`skewPolicy` in `~/.opm/config.cue`, or `Refuse` in the `Platform` resource's `spec.skewPolicy`). Check against: library/opm/errors/skew.go, cli/internal/config/templates.go, opm-operator/api/v1alpha1/platform_types.go --> |
| Apply | <!-- Sending rendered objects to the cluster with server-side apply and recording them in an inventory: `opm instance apply`, or an operator reconcile. Check against: cli/internal/cmd/instance/apply.go, opm-operator/internal/reconcile/moduleinstance.go --> |
| Inventory | <!-- The list of objects an instance deployed, kept in `status.inventory` on its `ModuleInstance` resource; pruning and deletion work from it. Check against: opm-operator/api/v1alpha1/common_types.go (`Inventory`), cli/internal/inventory/ --> |
| Prune | <!-- Deleting objects a new render no longer emits, and on deletion everything the inventory lists. The CLI prunes on apply unless `--no-prune`; the operator prunes only when `spec.prune` is `true`. Check against: cli/internal/cmd/instance/apply.go, opm-operator/internal/reconcile/moduleinstance.go --> |
| Owner | <!-- `spec.owner` on a `ModuleInstance`: `cli` (a CLI-managed instance, which the CLI renders, applies and prunes) or `operator` (an operator-managed instance, also meant by an absent value). Set at creation. Check against: opm-operator/api/v1alpha1/moduleinstance_types.go, cli/internal/inventory/ownership.go, cli/README.md --> |
| Operator | <!-- The opm-operator: a Kubernetes controller that reconciles `ModuleInstance`, `ModulePackage`, `Platform` and `TransformerRegistration` resources, fetching published modules from the registry. Installed with `opm operator install`. Check against: opm-operator/internal/controller/, cli/internal/cmd/operator/install.go --> |
| `ModuleInstance` | <!-- The namespaced custom resource (group `opmodel.dev`, version `v1alpha1`, short name `mi`) that records an instance on the cluster: `spec.module` (`path`, `version`), `spec.values`, `spec.owner`, `spec.prune`, and the inventory in its status. Check against: opm-operator/api/v1alpha1/moduleinstance_types.go, opm-operator/api/v1alpha1/groupversion_info.go --> |
| `ModulePackage` | <!-- The namespaced custom resource (short name `mpkg`) that renders an `instance.cue` package from a Flux source artifact at `spec.path`. Check against: opm-operator/api/v1alpha1/modulepackage_types.go --> |
| `TransformerRegistration` | <!-- The cluster-scoped custom resource (short name `treg`), called a claim, that a provider module ships to add its catalog to the platform: `spec.catalog`, `spec.version`, `spec.provides`, `spec.providerRef`; accepted or refused by the operator. Check against: opm-operator/api/v1alpha1/transformerregistration_types.go --> |
| Unresolved demand | <!-- A contract a component demands that no transformer on the platform supplies; fails the render (`UnresolvedDemandsError`). See the diagnostics entry "Unresolved demands". Check against: library/opm/errors/match.go --> |
| Unmatched component | <!-- A component no transformer matched; fails the render (`UnmatchedComponentsError`). See "No matching transformer". Check against: library/opm/errors/unmatched.go --> |
| Oversubscribed contract | <!-- A provider-fulfilled contract that transformers from more than one catalog require; fails the render (`OverSubscribedContractsError`) and is reported by `opm platform check`. See "Over-subscribed provider contracts". Check against: library/opm/errors/oversubscribed.go, core/src/platform.cue --> |
| Identity mismatch | <!-- A module fetched from the registry whose declared path or version disagrees with the coordinate it was fetched by (`IdentityError`). See "Identity mismatch". Check against: library/opm/errors/identity.go --> |
| Transform error | <!-- A matched transformer that failed to produce concrete output for a component (`TransformError`). See "Transform failed". Check against: library/opm/errors/domain.go --> |
| Registry mapping | <!-- The rule that sends a module path prefix to an OCI registry, such as `opmodel.dev=ghcr.io/open-platform-model`; set by `CUE_REGISTRY` for `cue`, and by `--registry`, `OPM_REGISTRY` or `registry` in `~/.opm/config.cue` for `opm`, in that order. Check against: cli/internal/config/resolver.go, cli/internal/config/templates.go, research/cue/cli/registryconfig.md --> |
| Module template | <!-- A published module under `opmodel.dev/templates` (`minimal`, `standard`, `advanced`) that `opm module init` copies and renames to start a new module. Check against: cli/internal/cmd/module/init.go, cli/internal/cmd/module/template.go --> |
| Publish gate | <!-- A core definition a publish command unifies an artifact against before publishing: `#IdentityPackage`, `#TraitOptionalGate`, `#CatalogMemberFQNGate`. A failure refuses the publish. Check against: core/src/identity_package.cue, core/src/trait.cue, cli/internal/publish/catalog_gates.go, cli/internal/cmdutil/publish.go --> |
| CUE | <!-- The configuration language OPM modules, catalogs and platforms are written in; it validates and evaluates data against schemas by unification. Check against: core/src/, research/cue/README.md --> |
| CUE module | <!-- A directory with `cue.mod/module.cue`, which names the module path and pins dependencies under `deps`; created with `cue mod init`, dependencies filled by `cue mod tidy`. Check against: cli/examples/cue.mod/module.cue, research/cue/cli/modules.md --> |
| Package | <!-- The CUE files in one directory that share a `package` clause and evaluate as one value; an instance file and its `values.cue` are one package. Check against: cli/examples/instances/podinfo/, research/cue/cli/modules.md --> |
| Import | <!-- An `import` of another CUE package by its path, such as `"opmodel.dev/core@v2"`; this is how an instance names its module and a platform names its catalogs. Check against: cli/examples/instances/podinfo/instance.cue, core/src/platform.cue --> |
| Definition | <!-- A CUE schema whose name starts with `#`, such as `#Module`; definitions are closed and are not emitted as data. Check against: core/src/module.cue, research/cue/concepts/closedness.md --> |
| Unification | <!-- CUE's one way of combining values, written `&`: the result satisfies both sides, and two different concrete values conflict. There is no override order. Check against: core/SPEC.md (section 6.1), research/cue/concepts/default-precedence.md --> |
| Conflict | <!-- The error unification reports when two sources disagree, printed as `conflicting values`. Check against: core/SPEC.md (section 6), research/cue/concepts/ --> |
| Concrete value | <!-- A value with no remaining choice, such as `3` or `"nginx"`; rendering needs every output field concrete. Check against: research/cue/concepts/concrete-partial-final.md, library/opm/errors/domain.go --> |
| Incomplete value | <!-- A value that is still a constraint or an unresolved choice, such as `int`; CUE reports it when a concrete value is needed, for example an unset required field. Check against: research/cue/concepts/concrete-partial-final.md, core/SPEC.md (section 5.1) --> |
| Required field | <!-- A field marked `!` (`name!: string`) that must be given a value. Check against: core/src/module.cue, research/cue/concepts/labels.md --> |
| Optional field | <!-- A field marked `?` (`labels?: …`) that may be left out. Check against: core/src/module.cue, research/cue/concepts/labels.md --> |
| Default | <!-- A value marked with an asterisk inside a disjunction (`replicas` in modules/web_app/module.cue defaults to 1 this way), used when nothing else sets the field; two different defaults on one field cancel out. The author must escape the vertical bar in any snippet placed in this table. Check against: core/SPEC.md (section 6.1), modules/web_app/module.cue, research/cue/concepts/default-precedence.md --> |
| Disjunction | <!-- A choice between values, written with a vertical bar between them, such as the `serviceType` field in modules/web_app/module.cue (ClusterIP, NodePort or LoadBalancer, defaulting to ClusterIP). The author must escape the vertical bar in any snippet placed in this table. Check against: modules/web_app/module.cue, research/cue/concepts/disjunctions.md, catalog_opm/docs/struct-disjunctions.md --> |
| Closed struct | <!-- A struct that refuses fields it does not declare (`field not allowed`); every definition is closed. Check against: research/cue/concepts/closedness.md, catalog_opm/docs/cue-guard-closedness-workaround.md --> |
| Hidden field | <!-- A field whose name starts with `_`, visible only inside its own package and never emitted. Check against: core/src/component.cue, research/cue/concepts/labels.md --> |
| Embedding | <!-- Writing a definition at the top of a file or struct, as in `core.#ModuleInstance` at the top of an instance file, so the whole value takes that shape. Check against: cli/examples/instances/podinfo/instance.cue, research/cue/concepts/embedding.md --> |
| Pattern constraint | <!-- A rule applied to every field whose name matches, written `[Name=string]: …`, as `#components` and `#registry` use. Check against: core/src/module.cue, core/src/platform.cue, research/cue/concepts/labels.md --> |
