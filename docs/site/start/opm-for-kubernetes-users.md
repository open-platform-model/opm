<!-- One sentence saying what the page lists: each OPM term a Kubernetes or Helm user meets, next to the closest idea they already know and the point where the comparison stops holding. Rows follow the product's structure: what a module is made of, what supplies rendering, identity, then deploying and the operator's resources. Each term's definition lives in the "Glossary"; this page gives only the analogy and its limit. No opinion. Check against: core/SPEC.md, cli/README.md, opm-operator/api/v1alpha1/ -->

| OPM term | Closest Kubernetes or Helm idea | Where the comparison stops |
| --- | --- | --- |
| Module | <!-- A Helm chart. Check against: core/src/module.cue --> | <!-- A module has no templates and names no Kubernetes kinds; it is a CUE module published to an OCI registry under a module path that carries its major (`opmodel.dev/modules/web_app@v1`), and its `metadata.name` is snake_case and equals the path's last segment. Check against: core/src/module.cue, core/SPEC.md (section 3.2) --> |
| Module configuration (`#config`) | <!-- A chart's `values.schema.json` together with the defaults in `values.yaml`. Check against: core/src/module.cue, modules/web_app/module.cue --> | <!-- Schema and defaults are one CUE definition (defaults marked with `*`); values passed with `-f` are unified with it and an unknown field is refused with `field not allowed`. Verify: values written inside the instance package are not checked for unknown fields (a misspelled key rendered silently in testing). Check against: core/src/module.cue, core/src/module_instance.cue, cli/internal/cmd/module/vet.go --> |
| `debugValues` | <!-- The values a chart author uses with `helm template` while developing. Check against: core/src/module.cue --> | <!-- Used only when the CLI builds a module directory without an instance file (`opm module build`, `opm module apply`, `opm module vet` without `-f`); never merged into an authored instance's values. Check against: cli/internal/cmd/module/build.go, cli/internal/cmd/module/vet.go, cli/internal/workflow/render/module.go --> |
| Values | <!-- `helm install -f values.yaml` and `--set`. Check against: core/src/module_instance.cue --> | <!-- Values are unified, not merged: a later file cannot override a value an earlier source set to something different, the two conflict and the render fails. `values.cue` next to an instance file is loaded without `-f`. Check against: library/docs/getting-started.md (layered values), library/opm/kernel/doc.go, cli/internal/cmd/instance/build.go --> |
| Component | <!-- One workload and the objects around it, such as a Deployment with its Service and HorizontalPodAutoscaler. Check against: core/src/component.cue --> | <!-- A component names no kinds; the platform's transformers decide which objects it becomes. Its rendered objects are named `<instance>-<component>` by default, overridable with `metadata.resourceName`. Check against: core/src/component.cue, core/SPEC.md (section 3.1) --> |
| Blueprint | <!-- Choosing the workload controller: Deployment, StatefulSet, DaemonSet, Job or CronJob. Check against: catalog_opm/opm/blueprints/v1beta1/ --> | <!-- A blueprint renders nothing itself; it composes resources and traits and answers the `core.opmodel.dev/workload-type` matching label, which selects the transformer. The five in `opmodel.dev/catalogs/opm@v4`: `stateless-workload`, `stateful-workload`, `daemon-workload`, `task-workload`, `scheduled-task-workload`. Check against: core/src/blueprint.cue, catalog_opm/opm/blueprints/v1beta1/, catalog_opm/opm/resources/v1beta1/container.cue --> |
| Resource | <!-- An API resource type such as a container spec, a volume, a ConfigMap or a Secret. Check against: core/src/resource.cue, catalog_opm/opm/resources/v1beta1/ --> | <!-- An OPM resource is an abstract noun, not a Kubernetes kind: the `container` resource becomes a Deployment, StatefulSet, DaemonSet, Job or CronJob depending on the blueprint. Raw Kubernetes kinds are separate resources in `opmodel.dev/catalogs/k8s@v1`, the escape hatch. Check against: core/src/resource.cue, catalog_opm/opm/resources/v1beta1/container.cue, catalog_opm/k8s/resources/v1/ --> |
| Trait | <!-- The settings and add-on objects you attach to a workload: a HorizontalPodAutoscaler, a PodDisruptionBudget, a Service, a security context. Check against: core/src/trait.cue, catalog_opm/opm/traits/v1beta1/ --> | <!-- A trait attaches only to a component whose resources it lists in `appliesTo`, or CUE refuses it; it can make a transformer emit its own objects (the `expose` trait yields a Service); its `optional` posture decides whether a trait no transformer handles fails the render or only warns. Check against: core/src/trait.cue, core/SPEC.md (section 2.2), catalog_opm/opm/traits/v1beta1/expose.cue --> |
| `matchLabels` | <!-- A label selector. Check against: core/src/component.cue, core/src/resource.cue --> | <!-- Matching happens at render time, never on the cluster: a transformer's `requiredLabels` is compared with the component's `matchLabels`, which come only from what the component attaches. Core never copies them onto objects, although the catalog's transformers write `core.opmodel.dev/workload-type` onto the objects they emit. Check against: core/src/component.cue, core/src/transformer.cue, catalog_opm/opm/transformers/deployment_transformer.cue --> |
| Transformer | <!-- One template file in a chart that emits one kind. Check against: core/src/transformer.cue --> | <!-- Transformers live in catalogs, not in the module, and are chosen by matching; a `#transform` is a CUE function evaluated at render, not a text template, and a component can match several transformers at once. Check against: core/src/transformer.cue, core/SPEC.md (section 4.1), catalog_opm/opm/transformers/ --> |
| Catalog | <!-- A library chart combined with an API group's CRD bundle. Check against: core/src/catalog.cue --> | <!-- A catalog is a versioned CUE module listing the resources, traits and blueprints it defines and the transformers it implements; it installs nothing on the cluster, and a platform imports it. Check against: core/src/catalog.cue, catalog_opm/opm/catalog.cue --> |
| Contract and `apiVersion` | <!-- Kubernetes API versions (`v1alpha1`, `v1beta1`, `v1`) on a group, version and kind. Check against: core/src/types.cue (`#APIVersionType`, `#ContractFQNType`) --> | <!-- A contract is keyed `<path>/<name>@<apiVersion>`, for example `opmodel.dev/catalogs/opm/resources/container@v1beta1`; the additive-only promise binds at beta and GA and not at alpha; the catalog's own release version is separate provenance (`catalogVersion`) and is not part of the key. Check against: core/src/types.cue (`#APIVersionGated`), core/src/resource.cue, core/SPEC.md (section 2.1) --> |
| Platform | <!-- The set of APIs and controllers a cluster offers, as API discovery shows it. Check against: core/src/platform.cue --> | <!-- A platform is a CUE module that imports its catalogs, pinned in its own `cue.mod/module.cue`. On a cluster it is the `Platform` resource, a cluster-scoped singleton named `cluster`; on a laptop the CLI uses `~/.opm/platform/` or a `--platform` directory. Check against: core/src/platform.cue, opm-operator/api/v1alpha1/platform_types.go, cli/internal/platform/resolve.go --> |
| Instance | <!-- A Helm release. Check against: core/src/module_instance.cue --> | <!-- Its UUID is computed from the module's registry path without the major, the instance name and the namespace, so it survives module upgrades including a major bump; rendered objects carry it in the `module-instance.opmodel.dev/uuid` label. Resource names follow the Helm fullname shape, `<instance>-<component>`. Check against: core/src/module_instance.cue, core/SPEC.md (section 3.5) --> |
| Module path and registry | <!-- An OCI chart reference (`oci://…`) or an image reference. Check against: core/src/types.cue (`#ModulePathType`) --> | <!-- The module path is a CUE import path with a `@vN` major; the exact version is a separate pin in the importing module's `cue.mod/module.cue`. Resolution goes through a registry mapping (`CUE_REGISTRY`, `OPM_REGISTRY`, or `registry` in `~/.opm/config.cue`), routed by longest path prefix, for example `opmodel.dev=ghcr.io/open-platform-model`. Check against: core/src/types.cue, cli/internal/config/templates.go, cli/internal/config/resolver.go --> |
| Module template | <!-- `helm create` and Helm starter charts. Check against: cli/internal/cmd/module/init.go --> | <!-- Templates are published modules under `opmodel.dev/templates` (`minimal`, `standard`, `advanced`), fetched from the registry by `opm module init`; `--from` starts from any published module instead. Check against: cli/internal/cmd/module/init.go, cli/internal/cmd/module/template.go --> |
| Render (`opm instance build`) | <!-- `helm template`. Check against: cli/internal/cmd/instance/build.go --> | <!-- A render needs a platform, and refuses when a component matches no transformer or a demanded contract has no provider, instead of emitting partial output. `opm instance build` and `opm instance vet` never contact the cluster. Check against: cli/internal/cmd/instance/build.go, library/opm/errors/unmatched.go, library/opm/errors/match.go --> |
| Apply (`opm instance apply`) | <!-- `helm upgrade --install`. Check against: cli/internal/cmd/instance/apply.go --> | <!-- The CLI uses server-side apply, records its inventory in a `ModuleInstance` resource (the CRD must be installed, `opm operator install --crds-only`), and prunes objects the new render no longer emits unless `--no-prune` is given. Check against: cli/internal/cmd/instance/apply.go, cli/internal/workflow/apply/apply.go --> |
| Inventory | <!-- The Helm release Secret (`sh.helm.release.v1.*`). Check against: opm-operator/api/v1alpha1/common_types.go (`Inventory`, `InventoryEntry`) --> | <!-- The inventory is `status.inventory` on the `ModuleInstance` resource, one entry per object (group, kind, namespace, name, version, component), written by whichever of the CLI or the operator owns the instance. Check against: opm-operator/api/v1alpha1/common_types.go, cli/internal/inventory/cr.go --> |
| Prune (`spec.prune`) | <!-- Flux Kustomization `spec.prune`. Check against: opm-operator/api/v1alpha1/moduleinstance_types.go --> | <!-- For an operator-managed instance the operator removes stale objects, and removes everything on deletion, only when `spec.prune` is `true`; the field has no default and the CLI never writes it. The CLI prunes on its own apply unless `--no-prune`. Check against: opm-operator/internal/reconcile/moduleinstance.go, cli/README.md, cli/internal/cmd/instance/apply.go --> |
| Owner (`spec.owner`) | <!-- No direct equivalent; nearest is a Helm release installed by hand compared with one a Flux HelmRelease manages. Check against: opm-operator/api/v1alpha1/moduleinstance_types.go --> | <!-- `cli` or `operator`, set when the instance is created; for `cli` the operator renders, applies and prunes nothing and records only a `ManagedExternally` acknowledgement; no command moves an instance between the two. Check against: opm-operator/api/v1alpha1/moduleinstance_types.go, cli/README.md, cli/internal/inventory/ownership.go --> |
| opm-operator | <!-- Flux's helm-controller reconciling a HelmRelease. Check against: opm-operator/internal/reconcile/moduleinstance.go --> | <!-- The operator fetches the module from the OCI registry by `spec.module.path` and `spec.module.version`, renders it against the cluster `Platform`, and cannot use a module that exists only as local files; `opm instance apply` refuses such a module for an operator-managed instance. Check against: opm-operator/api/v1alpha1/common_types.go (`ModuleReference`), opm-operator/internal/reconcile/moduleinstance.go, cli/README.md --> |
| `ModuleInstance` resource | <!-- A Flux `HelmRelease`. Check against: opm-operator/api/v1alpha1/moduleinstance_types.go --> | <!-- Namespaced, short name `mi`; `spec.module`, `spec.values`, `spec.prune`, `spec.owner`, `spec.suspend`, `spec.serviceAccountName`, `spec.rollout`; the same kind records CLI-managed instances. Check against: opm-operator/api/v1alpha1/moduleinstance_types.go, opm-operator/config/crd/bases/opmodel.dev_moduleinstances.yaml --> |
| `ModulePackage` resource | <!-- A Flux `Kustomization` with a `sourceRef` and a `path`. Check against: opm-operator/api/v1alpha1/modulepackage_types.go --> | <!-- It loads `instance.cue` at `spec.path` inside a Flux source artifact and renders it only when it evaluates to a `#ModuleInstance`; any other kind is refused. Short name `mpkg`. Check against: opm-operator/api/v1alpha1/modulepackage_types.go, opm-operator/internal/reconcile/modulepackage.go --> |
| `TransformerRegistration` resource | <!-- An `APIService` registering an aggregated API. Check against: opm-operator/api/v1alpha1/transformerregistration_types.go --> | <!-- A cluster-scoped claim, named `<namespace>.<name>` of the claiming instance, that a provider module ships among its rendered objects to add its catalog's transformers to the platform; creating one needs platform-admin RBAC, and a second provider for the same contract is refused at acceptance. Check against: opm-operator/api/v1alpha1/transformerregistration_types.go, opm-operator/api/v1alpha1/platform_types.go (`RegistryEntrySource`) --> |
| Kernel | <!-- Helm's Go SDK, embedded in another program. Check against: library/opm/kernel/doc.go --> | <!-- The kernel acquires, validates and renders; it applies nothing, so applying and pruning belong to the CLI and the operator that embed it. Check against: library/opm/kernel/doc.go, library/docs/getting-started.md --> |
